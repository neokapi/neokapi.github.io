Kapi Desktop

Kapi Desktop shows your projects' writing rules: terms, voice, and the decisions people made. While your assistants work, they suggest new rules. In the app you keep each one, change it, or drop it. A rule you keep applies to every file and every assistant.

The app, the kapi CLI and the MCP server use the same project data, so you get the same answer from each.

This page shows where to find each part of the app. Your first project walks through one project step by step, and the tour shows each part in a video.

Install​

On macOS, the cask installs the app and bundles the kapi CLI:

brew install --cask neokapi/tap/kapi

Installation covers the Windows installer, the macOS DMG, the Linux tarball and the release channels.

Your context​

When the app opens, you see Your context, a summary of every project in the workspace.

  • Counts for the workspace: projects, rules in use, terms, open suggestions, and items that need you. The last count is highlighted when two suggestions disagree.
  • What's new has a row for each project with something new, newest first. Each row shows the assistant, what it suggested, and Review or Decide. A live dot means an assistant is working in that project. Press j and k to move between rows and Enter to open one.
  • Projects lists every project you opened in the CLI or the app, or that an assistant set up. Each row shows the project's voice profile, its rules, and who the rules are shared with. Clones and worktrees of one project share a row and one set of rules, and the row's ⋯ menu lists each copy. If a project has no copy on this machine, it opens without the actions that need files.
  • Holds in every project lists the rules that apply to all your projects.
  • Start here has three steps for your first visit: try the sample, connect an assistant, and come back to see what it suggested. Dismiss it when you're done. You can turn it back on in Settings.
  • History, next to the title, opens the sessions of every project.

Each project opens in a tab, and the app reopens your tabs from last time. The sidebar has one entry per page: Overview, Context, Review and Project Settings, with App Settings at the bottom.

Overview​

A project opens on its Overview, the desktop form of kapi look.

  • Counts of files, blocks, rules and findings. Click a count to see what it counts. The findings count is highlighted when there are any.
  • First steps, on a new project: decide what becomes a rule, check the files, fix what fails, connect an assistant, and share the rules. Click a row to go to that step, or Guide to open Your first project. The list goes away when you have decided the rules, connected an assistant and shared the rules, or when you click Dismiss. The last line of kapi look shows the same next step.
  • What your files do lists the suggestions you haven't decided yet, each with a sentence where it was seen. Decide opens it in Decide.
  • Deeper look with AI uses your AI model to read the files and suggest more rules, like kapi context suggest --ai.
  • Files lists each content file with its blocks and findings, most findings first. Open shows it in the Reader.
  • Run on everything checks every file. The first time you open a project in a session, the Overview also runs the checks once.

The Reader shows a file's blocks in order and marks each finding on its words. Fix replaces the words with the rule's wording, and Fix n in this file fixes them all at once, keeping the file's formatting. Rules here shows the same rules as kapi context <path>.

Decide​

Decide is at the top of the Context page. Like kapi rules, it asks one question per suggestion, and you pick one of three answers:

AnswerKeyWhat it does
KeepkMakes it a rule in the terms, the voice profile or the content memory. If two suggestions disagree, keeps the one you picked.
Not a rulenRemoves it. Checks stop reporting it.
LaterlSaves nothing. Checks keep reporting it, and Decide asks again next time.

Until you decide, checks report a suggestion but never fail on it. Above the answers you see what keeping it does, and Seen in shows the sentence and file it came from. To decide, you need a copy of the project on this machine. Review what your assistant noticed walks through it on the sample.

The rest of the Context page​

Search finds rules by word or by file. Search for a word to see the terms that cover it and approved text that uses it. Search for a file to see the rules for that file.

Explore shows your rules by product, market and other dimensions, and over time: a timeline, flows, a matrix, a map of markets, and a list of records. One search filters every view. Explore your context goes through each view, and kapi context atlas --json prints the same data.

Voice, Terms and, in a project with target languages, Content Memory let you read and edit those stores directly.

Project Settings​

  • Assistants connects Claude Code, Cursor, VS Code, Codex, Agent skills or Claude Desktop, and writes the same files as kapi connect. Sessions lists what each assistant session suggested and, if the check on every edit is on, what it found. Show what it reads shows the rules files and the rules for one file. See Connect an assistant.
  • Sessions shows what one session changed and the checks it ran. Reset to before this session undoes the session's changes to your rules, and Take this reset back undoes the reset. It's the same as kapi context reset --before <session>.
  • Share shows who can see your rules: only this Mac, your team through git, a folder or S3, or a managed workspace. Sync now runs kapi context sync. See Share context with your team.
  • Content shows the collections, the files in each, and each file's format. Open a file to preview the text kapi reads from it.
  • Flows holds the project's flows. You can edit them and run them, with progress for each file. See Build a flow visually.

App Settings, at the bottom of the sidebar, holds the app's appearance and language, your AI models, plugins, the formats kapi reads with your saved settings for each, and the list of languages you pick from, where you can hide one or add your own.

In every language​

If a project has target languages, the Overview also shows Bring up to date, the desktop form of kapi up. Plan… shows the work to do and estimates the tokens it uses before anything runs. Next to it, three counts show the work: blocks to translate, blocks waiting for a person to review, and languages held back. Review shows the text that isn't ready to ship yet.

A project without target languages works as it is. Review lets you pick languages to translate into, and the views above appear when you add the first one.

The sample​

Try the sample opens KapiMart, a sample store with a voice profile, terms, a content memory and five target languages. It comes with two recorded assistant sessions, and one disagrees with the other, so Decide has a question for you right away. The sample doesn't call an AI model.

The project file​

Everything you set up is saved in the project's kapi.yaml file. Commit it to share it with your team, open it again in Kapi Desktop, or run it from the command line with kapi up -p kapi.yaml. Kapi Project Files is the full reference.
