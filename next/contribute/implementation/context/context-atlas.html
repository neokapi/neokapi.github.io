Context atlas

The context atlas is a single document that holds all of a project's context records. Each record sits at its point on the project's axes and carries the statuses it has held over time. Each event carries a recorded time and, where it differs, an effective time. host.App.ContextAtlas builds the document, kapi context atlas --json prints it, and the desktop's Explore view draws it. The field names below are the contract between these three. See C-11 for how the atlas relates to the other context operations, C-02 for typed axes, and C-12 for the places a geo axis holds.

Request​

type ContextAtlasRequest struct {
    Project     string // recipe path or workspace key; empty resolves as every command does
    AllProjects bool   // every project in the workspace; content cells and terms are omitted
    Content     bool   // include content cells (unit counts by collection, locale and state)
    Limit       int    // cap on records and on events; 0 is 5000
}

kapi context atlas sets Content unless --no-content or --all-projects is given. When Limit truncates the records or the events, the host adds an entry to notes with the counts.

Document​

type ContextAtlas struct {
    Format      string        `json:"format"`       // "kapi-context-atlas"
    Version     int           `json:"version"`      // 1
    Project     string        `json:"project,omitempty"`
    GeneratedAt time.Time     `json:"generated_at"`
    Span        AtlasSpan     `json:"span"`         // earliest..latest instant across records and events
    Axes        []AtlasAxis   `json:"axes"`
    Places      []AtlasPlace  `json:"places"`       // the gazetteer the map draws from
    Records     []AtlasRecord `json:"records"`
    Events      []AtlasEvent  `json:"events"`
    Notes       []string      `json:"notes"`        // scope of the read, truncation, data not read
}

type AtlasSpan struct {
    From time.Time `json:"from"`
    To   time.Time `json:"to"`
}

axes, places, records, events and notes are always JSON arrays. An empty one is written as [].

Axes​

type AtlasAxis struct {
    ID     string       `json:"id"`
    Label  string       `json:"label,omitempty"` // the recipe's label; empty when the recipe sets none
    Kind   string       `json:"kind"`            // category | geo | range | ordered
    Source string       `json:"source"`          // structural | declared | derived
    Values []AtlasValue `json:"values"`          // display order
}

type AtlasValue struct {
    ID    string `json:"id"`
    Label string `json:"label,omitempty"` // the recipe's label, or a place's name
}

A geo value carries only an id and a label. The place's containment, members and outline are in places, under the same id.

SourceAxesValues
structuralproduct, channelthe profiles and channels the recipe declares, and any a record uses
declaredevery axis axes: types or a coordinate names, and any other axis a record carriesa closed or ordered axis lists its declared values in order, then any other used; a geo axis lists the places the records use and every declared place, places made of places first, then by type from the widest kind to the narrowest (place.Type.Rank), then by name; a range axis lists used intervals by lower bound
derivedfamily, actor, project (with all_projects), locale, regionthe values the records use; region is a geo axis holding the place each locale names (place.OfLocale): the subdivision of a -u-sd- extension, else the country or M49 region of its region subtag

The view computes four further axes from the records, and the document does not carry them. They are the status at the start of the time window, the status at the snapshot, the lifetime (upcoming, in force, expired or open at the snapshot) and the time since the record was recorded.

Places​

type AtlasPlace struct {
    ID       string            `json:"id"`
    Name     string            `json:"name"`
    Names    map[string]string `json:"names,omitempty"`    // a declared place's names per locale
    Type     string            `json:"type"`               // world | region | country | subdivision | a declared type
    Within   []string          `json:"within,omitempty"`
    Of       []string          `json:"of,omitempty"`
    Centroid *[2]float64       `json:"centroid,omitempty"` // [lat, lon], rounded to two decimals
    Refs     []string          `json:"refs,omitempty"`
    Shape    string            `json:"shape,omitempty"`    // a declared place's GeoJSON file
    Geometry *AtlasGeometry    `json:"geometry,omitempty"` // the polygon that file holds
    Declared bool              `json:"declared,omitempty"`
}

type AtlasGeometry struct {
    Type        string `json:"type"`        // Polygon | MultiPolygon
    Coordinates any    `json:"coordinates"` // [lon, lat] positions in rings, as the file writes them
}

places is the part of the project's gazetteer a map needs, sorted by id. The host collects:

  1. every place a record names on a geo axis, the derived region axis included;
  2. every place that contains one of those (Gazetteer.Ancestors), and the members of each place made of places, recursively;
  3. every place the recipe declares, with what contains it and what it is made of;
  4. then, for each country and subdivision in that set, the places directly below it (Gazetteer.Children), and for each region, the countries it holds through its subregions.

The last step lets a map drill down by name. A map opened at Norway lists every Norwegian county, including counties with no records.

within and of carry the declarations unchanged. A view that applies the containment rules of C-12 to them gets the same results as the engine. @neokapi/context-atlas implements those rules in model/places.ts. The shared fixture core/place/testdata/containment.json tests the Go and the TypeScript implementations against the same cases.

A declared place with shape: carries geometry. The host reads the file from the checkout and reduces it to one Polygon or MultiPolygon geometry. It accepts a bare geometry, a Feature holding one, or a FeatureCollection of a single such Feature. The host omits the geometry when the file cannot be read, is larger than 1 MiB (atlasMaxShape), or holds any other GeoJSON. It then adds a note that names the recipe key, such as places.bergen.shape: places/bergen.geojson is larger than 1 MiB, so the place has no outline. When the project has no checkout on this machine, no place carries geometry, and the host adds a note for each shape file it did not read.

Records​

type AtlasRecord struct {
    ID          string               `json:"id"`
    Family      string               `json:"family"`  // rule | note | memory | term | content | import
    Label       string               `json:"label"`
    Weight      int                  `json:"weight"`  // 1, or the unit count of a content cell
    Coordinates map[string]string    `json:"coordinates"`
    Recorded    time.Time            `json:"recorded"` // zero when unknown
    ValidFrom   *time.Time           `json:"valid_from,omitempty"`
    ValidTo     *time.Time           `json:"valid_to,omitempty"`
    History     []AtlasState         `json:"history"`  // time order
    Short       string               `json:"short,omitempty"`
    Actor       *contextop.Actor     `json:"actor,omitempty"`
    Evidence    []contextop.Evidence `json:"evidence,omitempty"`
    Text        string               `json:"text,omitempty"`
    Scope       string               `json:"scope,omitempty"`
    ContestedBy []string             `json:"contested_by,omitempty"`
}

type AtlasState struct {
    At    time.Time `json:"at"`
    State string    `json:"state"`
}

The state of a record at an instant is the last history entry at or before that instant. Before the first entry, the record does not exist.

FamilySourceidStates
rulean operation carrying a term rulethe operation idsuggested, established, contested, withdrawn, dropped, reset
notean operation carrying prosethe operation idas above
memoryan operation carrying a content-memory pairthe operation idas above
terma concept in the terms storeterm:<concept> (a concept id that starts term: is used as it is)established
contenta cell of kapi status coveragecontent:<collection>:<locale>:<state>not-started, draft, translated, established, stale

How each part is built:

  • Operations. Every operation that carries a subject becomes a record, oldest first. The subject sets the family: rule for a term rule, memory for a content-memory pair, note for prose. An import operation has the family import. The rows of the imported file become term and content-memory records, and the import record is their provenance. The history comes from Ledger.Histories. It starts with the initial status at the operation's own instant and adds each change at the instant of the operation that made it. When the log holds more than contextop.HistoryLimit instants, each history holds only the first status and the current one, and the host adds a note. A correction recorded without a rule carries no subject, so it appears only as an event.
  • Terms. Each concept becomes one record at the coordinates the concept is scoped to. When those coordinates omit product, the host sets it from the concept's profile. The label is the head term followed by the forms it discourages. The window is that of the first discouraged form that has one, or else that of the first term that has one. A rule a person kept produces two records with distinct ids: a rule record for the log entry and a term record for the concept in the terms store.
  • Content cells. The host measures the project with the same tally as kapi status (ProjectCoverageTally), one file at a time. It adds one record per collection, locale and state, weighted by its unit count. A stale unit is counted under stale and excluded from draft. The tally holds only the current state of each unit. Each cell therefore has one history entry, at generated_at, and a note states that earlier states are unknown.

Every record's coordinates holds the record's point and the derived axes. family is always set. An operation also carries actor (a person, an agent or a tool). project is set when the atlas covers every project. A content-memory pair, a term and a content cell carry locale and region.

Events​

type AtlasEvent struct {
    ID        string           `json:"id"`
    At        time.Time        `json:"at"`                  // recorded clock
    Effective *time.Time       `json:"effective,omitempty"` // effective clock when it differs
    Kind      string           `json:"kind"`                // an operation kind | term-added | window-opens | window-closes
    Record    string           `json:"record,omitempty"`    // the record it bears on
    Actor     *contextop.Actor `json:"actor,omitempty"`
    Label     string           `json:"label,omitempty"`
}

Each context operation produces an event at the instant the log accepted it. record names the record of the operation's subject when that record is in the atlas. A record with a window produces window-opens and window-closes events. Their at is the instant the window was set, by the operation that recorded the record or by the keep that added the window. Their effective is the bound. A profile with a validity window in the recipe produces the same two kinds at its bounds. These events have no record, and their at is the bound. A concept with a creation date in the terms store produces a term-added event at that date. The host does not read unit decisions and adds a note stating that.

Drawing the places​

The map in @neokapi/context-atlas draws places over built-in outlines that ship in the package under src/geo/:

FileHoldsKeyed by
world.jsonevery country, object countriesISO 3166-1 alpha-2 in lower case (no)
admin1/<cc>.jsonone country's subdivisions, object subdivisions, and its outline, object outlineISO 3166-2 in lower case (no-03)

Both are TopoJSON, simplified and quantised. The world file loads with the map. A country's file is a separate chunk, loaded when the map drills into that country. The data is Natural Earth (public domain) at a pinned release: the admin-0 countries and the admin-1 states and provinces. Where Natural Earth files subdivisions under an ISO 3166-2 region, the region's shape is the union of its parts and is keyed by the region's id (fr-ara).

scripts/build-geometry.mjs regenerates the directory:

vp run @neokapi/context-atlas#build-geometry

It downloads the two Natural Earth files at the pinned release, checks their SHA-256 digests, keys every feature by place id, simplifies each shape relative to its size, and writes the TopoJSON. --cache <dir> reads files already downloaded to <dir>. Natural Earth carries some subdivisions under a code that ISO 3166-2 has since replaced, or only as the parts of a current subdivision. For each of these, scripts/geometry-successors.json lists the current id, the features that compose it, and the ISO change or parent relation behind the mapping. The script unions the parts. The build fails on a row that names a code missing from Natural Earth, or an id that Natural Earth already carries. src/geo/README.md lists the release, the licence and the ids that have no outline.

A place with no outline in either file is drawn at its centroid when it has one, and is otherwise listed beside the map. The outlines are used only for drawing. Containment comes from the within and of declarations.

Cost​

The host reads the operation log once for the records and once more for the histories. The history pass folds the log at each distinct instant, up to contextop.HistoryLimit instants. The host reads the whole terms store, as kapi context search does. For content cells it reads every file of the project once per target language, as kapi status does. It keeps the counts and discards the blocks.
