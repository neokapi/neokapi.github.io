Translation reuse report

When an author edits an English sentence, kapi decides whether the approved Norwegian still applies. Four evals run that decision on real cases and show what the tool wrote each time.

How this is measured

AI models used Evals 1 to 4 use none. Every figure in them comes from running kapi’s own resolver, matcher, segmenter, recycle tool and prompt builder, so the results are exact rather than sampled. Eval 5 calls claude-code:sonnet and is the only one that does; its data is committed rather than regenerated, so the rest of the page stays deterministic.
Pass bar Tests in scripts/coordinatereport fail the build if the data in evals 1 to 4 stops matching the code, if the two reuse rules stop disagreeing, or if a case is added whose hand-written label disagrees with kapi’s own verdict. Eval 5 has no build gate: it samples a model, so a threshold on it would fail the build on a bad day. Its consistency half is a deterministic string check and its judged half is reported as unvalidated.
Not measured here Whether the judge in eval 5 agrees with a person. Until that agreement is measured on labelled examples, the judged win-loss numbers are reported and not relied on. The consistency numbers beside them need no such caveat.

Terms used below

Match score How similar the new English is to the English that was approved, as a percentage. kapi’s matcher compares the two texts character by character, so the score falls as more characters differ. The same one-character edit therefore scores higher in a long sentence than in a short one.
Verdict kapi’s classification of the edit, from comparing the two texts word by word rather than character by character. none: identical. cosmetic: the same words in the same order, differing only in punctuation, capitals, spacing or quote shape. substantive: a word was added, removed or changed. Sentence length does not affect it.
Reuse Writing the approved translation into the target file as a draft for review. The alternative is leaving the target empty, so the sentence goes to a translator or a model instead.
Old and current rule The old rule reuses whenever the match score is 95% or better. The current rule reuses whenever the verdict is none or cosmetic , and ignores the score.

Result

The two rules agree on 9 of the 11 edits and disagree on 2, highlighted above. In both, the meaning of the English changed and the old rule still wrote the old Norwegian into the file.

Raising the threshold would not fix it. Those two edits score 97% and 95%, higher than every edit the old rule correctly declined. A full stop added to a short button label scores 91%. Any threshold that catches the meaning changes also rejects harmless punctuation edits, and any threshold that keeps the punctuation edits lets the meaning changes through. The match score puts them in the wrong order, so no threshold sorts them correctly.

The current rule compares words instead. Adding “not” is a word change in a two-word label and in a paragraph alike, so sentence length stops affecting the decision.

Eval 5 of 5 spends model calls

Does the old translation change what the model writes

Everything above is deterministic. This one calls a model. Each edited sentence is translated twice, once with the previously approved translation in the prompt and once without, and the outputs are compared.

Model under test claude-code:sonnet (anthropic), 1 samples per case per arm
Judge ollama:gemma4:e2b (google). Refused at startup if it shares a family with the model under test, because a model grading its own family prefers itself measurably. Blind: it never sees which candidate had the reference, nor the reference, and the display order alternates.
Consistency check A whole-word search for the approved wording and for the word a model reaches for instead. Deterministic, so this half cannot be wrong about itself. It matches whole words rather than substrings, because Norwegian handlekurven contains kurven, and the first version of this check scored every drift as a match.
Run 2026-08-27T05:24:05Z. Committed rather than regenerated per build, so the rest of this page stays deterministic.

The path production runs

Everything above translates one sentence per call. Production batches, and the two build materially different prompts: a batch sends a JSON payload of many segments and a schema-constrained reply. So the same question is asked again over a document of 20 blocks, 5 of which carry a wording under test, in three arms.

      "text": "Add this to your cart",
      "key": "t-the-basket",
      "prior": {
        "was": "Add to your cart",
        "approved": "Legg i kurven"

}

Two things follow. Batching does not cost the effect — the batched arm with references matches the one-call-per-block ceiling exactly, so the worry that a model juggling many references would apply each less reliably did not materialise here. And the references are nearly free: 310 more input tokens across the document, for 3 of 5 becoming 5 of 5.

The third arm is what the old rule would have cost. A block with history used to be translated alone, because the batch payload had nowhere to put a per-segment reference — 20 calls and 543,281 input tokens to reach the same answer the batched arm reached in 2.

One caveat on the first row: the arm with no references is the one that varies between runs, scoring 2 of 5 and 3 of 5 on two runs of this document. The arm with references scored 5 of 5 both times. That is the shape you would expect if the reference is doing the work — but it is two runs, not a distribution.

Terminology is scoped to each call the same way: this collection is governed by 20 term rules and a call carries the 2 its own text could use. Tokens are the smaller saving; the larger is that the rules which do bite are not buried among the ones that cannot.

Result

The approved wording survived 5 of 6 times with the reference and 3 of 6 without it. The effect is concentrated: in three cases the model picks the house wording either way, and in two it never does without being shown it. Those two go from 0 of 3 to 3 of 3.

The control is what makes that readable. It is the same sentence as the first case, run with the reference withheld, and it produces the drifted wording in both arms, every time. So the difference above comes from the reference and not from the case.

The blind judge said 0 for the reference arm, 2 against and 4 ties, which is not evidence of anything yet: agreement with a human has not been measured, and the judge is a small local model. It is also asked the wrong question for this purpose. It sees the English and the two candidates, not the approved wording, so on the subscription case it preferred plan over abonnement — a defensible translation of the English and the wrong word for this product. Consistency is not visible to a judge that does not know what was agreed, which is why the measurement above it is a string check rather than an opinion.

Which rules apply where

Content sits at a coordinate: a product and a channel. The voice profile and the terms that govern it are attached to that coordinate rather than to the file, and eval 3 compares fingerprints of exactly those. The test project declares content at three of the four crossings.
