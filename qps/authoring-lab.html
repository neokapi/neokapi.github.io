Style Rules

Filtering by file type in ripgrep

Globs get repetitive. If you keep typing rg 'fn run' -g '*.rs', ripgrep already has a name for that set of files:

$ rg 'fn run' --type rust
$ rg 'fn run' -trust

A type is nothing more than a name bound to one or more globs. rust is *.rs; go is *.go; c is *.[chH], *.[chH].in and *.cats. ripgrep ships with more than 200 such names (crates/ignore/src/default_types.rs), and several have aliases — py/python, md/markdown, ts/typescript, bat/batch are interchangeable.

--type / -t: search only these

-t is repeatable and the results union: rg -tpy -tjs TODO searches Python and JavaScript files. Once any -t is in play ripgrep switches to whitelist mode — a file that matches no selected type is skipped.

Two properties are worth internalising, because they explain most surprises.

Type globs match the file name, not the path. ripgrep extracts the base name and tests the globs against that alone. *.rs matches src/deep/lib.rs because the name is lib.rs. It also means a type glob containing a / can never match, and that types like make work by naming files outright ([Mm]akefile, *.mk, *.mak).

Types never apply to directories. The matcher returns "no opinion" for any directory, so -t filters the files ripgrep reports, it doesn't prune the walk. Use -g '!vendor/' if you want to skip a tree.

-t also sits low in the precedence chain. ripgrep consults -g/--glob overrides first and returns immediately on a hit; then ignore-file rules, where an ignore match also returns immediately; only then types. So a file excluded by .gitignore stays excluded no matter what -t you pass — reach for -u/--no-ignore to override that, not for a type.

--type-not / -T: search everything but these

-T is the mirror image: rg clap -Trust searches everything except Rust files, and -T is likewise repeatable. Mixing the two is fine (rg -ttoml -Tjson pattern). When a file matches both a selected and a negated type, the flag given later on the command line wins — ripgrep keeps selections in argument order and the last matching glob takes precedence.

The special value all

--type all behaves as if you had passed -t for every type ripgrep currently knows, custom ones included. That is whitelist mode: search only files ripgrep recognises. --type-not all is the inverse — search only the unrecognised files.

The asymmetry catches people. Given my-shell-script (no extension) and my-shell-library.bash, both -tsh and -tall find only the .bash file, since no sh glob matches an extensionless name; -Tall finds only my-shell-script. -Tall is a decent way to spot files ripgrep has no type for.

--type-add: define your own

$ rg --type-add 'web:*.{html,css,js}' -tweb title

The format is name:glob, one glob per flag, and the flag is repeatable — the three-flag form ('web:*.html' 'web:*.css' 'web:*.js') is equivalent. Globs add to whatever that name already has, so --type-add 'py:*.pyx' extends the built-in py rather than replacing it. To replace, clear first: --type-clear py --type-add 'py:*.pyx'.

There is also an include directive that composes existing types:

$ rg --type-add 'src:include:cpp,py,md' -tsrc pattern
$ rg --type-add 'src:include:cpp,py,md' --type-add 'src:*.foo' -tsrc pattern

Two ordering rules follow from how ripgrep applies these left to right: every name in an include: list must already be defined at that point, and any --type-add you want -tall to pick up must come before it.

Names must be Unicode letters or numbers only — no punctuation, and all is reserved. A malformed spec fails with invalid definition (format is type:glob, e.g., html:*.html); selecting a name that doesn't exist fails with unrecognized file type: <name>, which is also what --type-clear rust -trust gets you.

Nothing is persisted. --type-add applies to that one invocation. To make a type permanent, alias it:

alias rg="rg --type-add 'web:*.{html,css,js}'"

or put it in a config file pointed at by RIPGREP_CONFIG_PATH, one shell argument per line, no escaping:

--type-add
web:*.{html,css,js}

--type-list: see what's defined

$ rg --type-list | rg '^go:'
go: *.go

Each line is name: glob, glob, ..., sorted by name with globs sorted within each line. It reflects any --type-add and --type-clear on the same command, so it doubles as a way to check a definition before you rely on it:

$ rg --type-add 'web:*.{html,css,js}' --type-list | rg '^web:'

It exits nonzero only if there are no definitions left to print. Since types are searchable text, rg --type-list | rg yaml is the fastest way to answer "does ripgrep know about this format, and under what name?"

Filtering by file type in ripgrep

A file type in ripgrep is just a name attached to one or more file name patterns. rust means *.rs. make means *.mak, *.mk, GNUmakefile, Gnumakefile, Makefile, gnumakefile, makefile. That's the whole idea. The four flags below let you use those names, list them, and define your own.

See what you already have

Start here:

$ rg --type-list

Each line is a type name, a :, and then a comma-delimited list of the patterns that make it up. ripgrep ships with more than 200 type names, so pipe the output through ripgrep itself when you're looking for one:

$ rg --type-list | rg '^make:'
make: *.mak, *.mk, GNUmakefile, Gnumakefile, Makefile, gnumakefile, makefile

Some types have aliases. py and python are the same type, as are md and markdown. --type-list also reflects any types you added or cleared in the same command, which makes it the fastest way to check a definition you just wrote.

-t/--type: only these files

$ rg 'fn run' --type rust
$ rg 'fn run' -trust

Both forms work; the short flag takes its value with no space. Pass the flag more than once to search several types at once:

$ rg 'TODO' -trust -tmd

Naming a type that doesn't exist is an error, not a silent no-op:

$ rg -tnope title
rg: unrecognized file type: nope

-T/--type-not: everything but these files

$ rg clap --type-not rust
$ rg clap -Trust

-t means "include files of this type", -T means "exclude files of this type". You can mix them, and here order matters. When a file matches both an included and an excluded type, the flag written later on the command line wins:

$ rg --type-add 'foo:*.{rs,foo}' -tfoo -Trust title
main.foo:title

$ rg --type-add 'foo:*.{rs,foo}' -Trust -tfoo title
main.foo:title
main.rs:title

Note that type filters have lower precedence than the -g/--glob flag and than any rules in your ignore files. If your .gitignore excludes a file, -t won't bring it back.

--type-add: define your own

The format is name:glob, and one glob per flag:

$ rg --type-add 'web:*.html' --type-add 'web:*.css' --type-add 'web:*.js' -tweb title

A brace alternation gets you the same thing in one flag:

$ rg --type-add 'web:*.{html,css,js}' -tweb title

By default, globs are added to whatever ripgrep already defines for that name, so --type-add 'md:*.markdown' extends the built-in md type rather than replacing it. Type names must consist only of Unicode letters or numbers — my-web is rejected — and all is reserved.

You can also build a type out of other types with the include directive:

$ rg --type-add 'src:include:cpp,py,md' -tsrc title

Every name after include: must already be defined at the point the flag is read, so put your --type-add definitions before any include that uses them. If one name in the list is bad, the whole definition is rejected and nothing changes. You can keep adding plain globs to an included type afterward:

$ rg --type-add 'src:include:cpp,py,md' --type-add 'src:*.foo' title

What the globs match

Type globs are matched against the file name only, never the full path. So --type-add 'web:src/*.js' will never match anything — use -g for path patterns and save types for names. Types also don't apply to directories.

This is also why a file with no extension slips through most types. A shell script named my-shell-script isn't matched by -tsh, because the sh globs all require an extension.

--type-clear and the all type

--type-clear NAME throws away the existing globs for a type, and you can add new ones afterward. Order matters:

$ rg --type-clear md --type-add 'md:*.markdown' --type-list | rg '^md:'
md: *.markdown

Reverse those two flags and the clear wipes out your addition too.

Both -t and -T accept the special value all. -tall searches every file matched by any defined type, custom types included — whitelist mode, where ripgrep only searches files it recognizes. -Tall is the inverse: it searches only the files no type recognizes. That's the fast way to find your extensionless scripts, stray data dumps, and anything ripgrep doesn't have a name for yet.

Making a type stick

--type-add and --type-clear apply to the current command only. Nothing is persisted. To get a type in every invocation, either alias it:

alias rg="rg --type-add 'web:*.{html,css,js}'"

or put it in your configuration file, one argument per line:

--type-add
web:*.{html,css,js}

ripgrep reads that file from the path in RIPGREP_CONFIG_PATH, and it won't look anywhere else. Once it's there, -tweb works everywhere, and --type-list will show web alongside the built-ins.

Filtering by file type in ripgrep

A file type in ripgrep is just a name attached to one or more globs. rust means *.rs; c means *.[chH], *.[chH].in and *.cats. Instead of retyping -g '*.{c,h}' on every search, you name the set once and reuse it. ripgrep ships with just over 200 built-in type definitions, and a handful have aliases — py and python, md and markdown, ts and typescript, bat and batch — so you can spell them the way you think of them.

-t/--type: search only these files

$ rg 'fn run' --type rust
$ rg 'fn run' -trust          # short form; the value attaches directly

Repeat the flag to widen the net — multiple -t flags are OR'd:

$ rg TODO -trust -tmd

The moment you pass a single -t, ripgrep switches into whitelist mode: a file that matches no selected type is skipped. This is the flag's real value on a large tree — you are not just filtering output, you are not opening the files at all.

--type=all is a special value meaning "every type currently defined, including ones you added on this command line." It is whitelist mode over ripgrep's whole type table: recognized files get searched, unrecognized ones don't. A shell script named my-shell-script with no extension isn't matched by the sh globs, so -tall skips it.

If you name a type that doesn't exist, ripgrep errors out rather than quietly matching nothing — a typo'd -tpyton fails loudly.

-T/--type-not: skip these files

$ rg clap --type-not rust
$ rg clap -Trust

-T is the mirror image and also repeatable. The asymmetry worth knowing: -t puts everything else out of scope, while a lone -T only removes the named type and leaves everything else searchable as usual.

You can mix them. When a file matches globs from more than one selection, the last one on the command line wins, so ordering is how you carve out exceptions:

$ rg config -tall -Tjson       # every recognized type except JSON

--type-not=all is the inverse of --type=all: it searches only files ripgrep doesn't recognize. That's a good way to find the strays — extensionless scripts, odd config files — that your type-based searches have been missing.

--type-list: see what a type actually covers

$ rg --type-list | rg '^make:'
make: *.mak, *.mk, GNUmakefile, Gnumakefile, Makefile, gnumakefile, makefile

One type per line, name, then : , then its globs comma-separated; both the list and each type's globs are sorted. Reach for this before you assume a type covers what you think — js includes *.vue, *.cjs and *.mjs; css includes *.scss; json includes composer.lock. --type-list also reflects any --type-add and --type-clear flags in the same invocation, which makes it the way to check a custom definition before searching with it.

--type-add: define your own

The format is NAME:GLOB, one glob per flag, additive to whatever ripgrep already defines for that name:

$ rg title --type-add 'web:*.html' --type-add 'web:*.css' -tweb
$ rg title --type-add 'web:*.{html,css,js}' -tweb        # same thing

Defining a type does not select it — you still need -tweb.

There is also an include directive that composes existing types:

$ rg --type-add 'src:include:cpp,py,md' -tsrc PATTERN
$ rg --type-add 'src:include:cpp,py,md' --type-add 'src:*.foo' -tsrc PATTERN

Included types must already be defined by the time the flag is parsed, so put your --type-add 'wat:*.wat' before the --type-add 'combo:include:wat,py' that references it. Type names must be only Unicode letters or numbers — no punctuation — and all is reserved.

The related --type-clear NAME wipes a type's globs entirely; you can add new ones afterward, but --type-clear rust -trust with nothing added back is an error, because rust no longer exists.

None of this persists. Type settings apply to one invocation only. To keep a definition, use a shell alias or a config file pointed at by RIPGREP_CONFIG_PATH, one argument per line:

--type-add
web:*.{html,css,js}

Things that will bite you

  • Type globs match the file name only, not the path. --type-add 'foo:src/*.rs' will never match. Use -g for path-shaped patterns.
  • Types lose to globs and to ignore files. Precedence runs --glob first, then ignore rules, then types. A gitignored file stays unsearched no matter what -t you pass; add -u/--no-ignore if you want it back.
  • Explicit paths bypass filtering. rg -tpy foo main.rs searches main.rs. Type filtering applies to files ripgrep discovers by walking, not to ones you hand it.
  • Types never apply to directories, so -t doesn't prune the traversal — it prevents files from being read and searched.
