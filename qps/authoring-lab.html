- Emotion: neutral

File Type Filtering in ripgrep

Searching your codebase is often about finding patterns in specific kinds of files. You might want to search only Python files, or exclude all the vendored JavaScript, or limit your results to configuration files. This is where ripgrep's file type filtering comes in. Instead of writing out glob patterns every time, you can use simple, memorable type names that ripgrep knows about.

What are file types?

A file type in ripgrep is a name that represents one or more file patterns (globs). For example, the rust type corresponds to all files matching *.rs. The c type matches both C source files (*.c) and header files (*.h and *.H). Ripgrep ships with over 200 predefined types covering the major programming languages and file formats in common use.

File types are just a convenience layer on top of glob patterns. When you use rg 'pattern' --type rust, it's equivalent to rg 'pattern' -g '*.rs'. The type approach saves you from having to remember which extensions belong to each language or format.

Selecting files with --type

The --type flag (short form: -t) tells ripgrep to search only files of a specific type. For example, to search for function definitions only in Rust files:

rg 'fn run' --type rust

Or more concisely:

rg 'fn run' -trus

You can use multiple --type flags to include multiple file types in your search:

rg 'TODO' --type rust --type go --type python

This searches for "TODO" comments across three programming languages at once.

Excluding files with --type-not

Sometimes it's easier to say what you don't want to search. The --type-not flag (short form: -T) excludes files of a specified type:

rg 'console.log' --type-not javascript

This searches for "console.log" everywhere except JavaScript files. Like --type, you can use --type-not multiple times:

rg 'import' --type-not python --type-not go --type-not rust

This searches for "import" in any file type except Python, Go, and Rust.

The distinction between --type and --type-not matters for whitelist vs. blacklist behavior. When you use --type, ripgrep searches only files matching those types. When you use --type-not, ripgrep searches all files except those types, including files that don't match any known type. This is useful when you're searching text that might appear in miscellaneous files ripgrep doesn't have a specific type for.

Discovering available types with --type-list

To see what types ripgrep knows about, use the --type-list flag. This prints every available type and its corresponding globs:

rg --type-list

The output looks like this:

ada: *.adb, *.ads
agda: *.agda, *.lagda
asm: *.asm, *.s, *.S
c: *.[chH], *.[chH].in, *.cats
cpp: *.[ChH], *.cc, *.[ch]pp, *.[ch]xx, *.hh, *.inl, *.[ChH].in, *.cc.in, *.[ch]pp.in, *.[ch]xx.in, *.hh.in
go: *.go
python: *.py
rust: *.rs

Each type is shown on its own line, followed by a colon and a comma-delimited list of globs. If you need to remind yourself which extensions belong to a language you don't work in often, --type-list has you covered.

You can pipe --type-list output to ripgrep itself to find types matching a pattern:

rg --type-list | rg '^make:'

This shows you exactly what patterns the make type includes.

Creating custom types with --type-add

The built-in types cover most languages and formats, but sometimes you need something custom. The --type-add flag lets you define new types for your search:

rg 'title' --type-add 'web:*.html' --type-add 'web:*.css' --type-add 'web:*.js' --type web

This defines a custom web type that includes HTML, CSS, and JavaScript files, then searches only those files for "title". You can make this more concise using the glob braces syntax:

rg 'title' --type-add 'web:*.{html,css,js}' --type web

Important: types defined with --type-add are temporary

The types you create with --type-add exist only for that one ripgrep invocation. If you exit your shell and run the command again later, ripgrep won't know about your custom type anymore. This is by design—types are not persisted to disk.

If you want a custom type to be available every time you run ripgrep, add it to your ripgrep configuration file. Create or edit ~/.ripgreprc (or set $RIPGREP_CONFIG_PATH to point to a different location) and add lines like:

--type-add=web:*.{html,css,js}
--type-add=data:*.json
--type-add=data:*.yaml

Now you can use rg 'pattern' --type web without having to specify --type-add on the command line each time.

The special all type

Ripgrep recognizes a special type called all that refers to every file type ripgrep knows about. Using --type all is equivalent to running --type rust --type python --type go and so on for every single built-in type plus any custom types you've added:

rg 'pattern' --type all

This is rarely what you want for a search—you're usually looking at a specific subset of files. But --type-not all has a specific and useful purpose: it searches only files that don't match any known file type. These might be configuration files without standard extensions, documentation files, or other miscellaneous text:

rg 'pattern' --type-not all

This searches in "blacklist" mode, finding your pattern in any file that ripgrep's type system doesn't recognize.

Practical examples for daily work

Here are some common scenarios for people who search code for a living:

Search for a symbol only in your primary language:

rg 'User\(' --type rust

Look for TODO comments everywhere except in third-party libraries:

rg 'TODO|FIXME' --type-not javascript --type-not node_modules

Audit all shell scripts in a monorepo:

rg 'eval\(' --type sh

Search for hardcoded API endpoints in frontend code:

rg 'api\.example\.com' --type-add 'frontend:*.tsx' --type-add 'frontend:*.jsx' --type-add 'frontend:*.ts' --type frontend

Find all imports in a polyglot repository, but exclude generated code:

rg '^(import|require|from)' --type rust --type python --type go

Performance and filtering precedence

File type filtering works with ripgrep's other filtering mechanisms. By default, ripgrep still respects .gitignore, .ignore, and .rgignore files, skips binary files, and skips hidden files. Type filtering adds an additional layer on top of these—it narrows your search space further by file extension or name.

The order of precedence is: ripgrep's automatic filters (ignore files, binary detection, hidden files) first, then glob patterns (including type globs). This means even if you use --type rust to include only Rust files, ripgrep will still exclude those that match your .gitignore.

When to use types vs. globs

For one-off searches, you might wonder whether to use --type python or -g '*.py'. If you already know the file extension pattern, globs are simpler and require no configuration. But types shine when:

  • The type matches multiple extensions (like c for *.c, *.h, and *.H)
  • You search the same type repeatedly (type names are easier to remember and type)
  • You want to share your search commands with teammates (they'll understand --type go more readily than -g '*go')
  • You need configuration-file persistence (types in ~/.ripgreprc work without duplicating --type-add flags)

Summary

File type filtering in ripgrep is built on three commands:

  • --type TYPE includes only files of a specified type
  • --type-not TYPE excludes files of a specified type
  • --type-list shows all available types and their globs
  • --type-add TYPESPEC creates a temporary custom type for the current command

For types you use frequently, define them once in your ripgrep configuration file and never think about file patterns again. For everything else, --type-list is one command away.

ripgrep File-Type Filtering

When you search across a large codebase or project, most of your results come from the files you actually want to search. ripgrep offers file-type filtering—a way to define reusable names for sets of file patterns—so you don't have to type the same glob patterns repeatedly.

What is a file type?

A file type is a named set of glob patterns. ripgrep ships with dozens of predefined types (rust, python, java, markdown, etc.), each corresponding to a file extension or set of extensions. The c type, for example, matches both *.c and *.h files, so you don't have to write -g '*.{c,h}' every time.

File-type filtering sits between glob patterns and your search. Both are optional: you can search without filters at all, use globs alone, use types alone, or combine them. When you do combine them, glob patterns have higher precedence; type filters are lower priority and won't override what you've explicitly specified with globs.

The --type flag: include specific types

Use --type (or -t for short) to search only files matching a particular type:

$ rg 'fn run' --type rust

This searches only Rust source files. You can combine multiple types by repeating the flag:

$ rg 'TODO' --type rust --type python

This searches both Rust and Python files for the pattern TODO.

Short-form usage combines flags: -trust -tpython is equivalent to --type rust --type python. You can also chain single-letter flags on one dash: -trust selects the rust type.

The --type-not flag: exclude specific types

Use --type-not (or -T for short) to exclude files of a particular type:

$ rg 'config' --type-not json

This searches everything except JSON files. Like --type, you can repeat it:

$ rg 'TODO' --type-not test --type-not vendor

This searches for TODO comments everywhere except test and vendored-dependency files.

Short form: -Trust -Tpython excludes both rust and python types. Similarly, -Trust is shorthand for --type-not rust.

The --type-add flag: define custom types

The predefined types cover common languages and formats, but your codebase might have custom file formats, unusual naming conventions, or a mix of file types you want to search together. The --type-add flag lets you define new types on the fly:

$ rg --type-add 'web:*.{html,css,js}' -tweb 'className'

This defines a new type called web matching HTML, CSS, and JavaScript files, then searches only those files for className.

You can add multiple globs to a type by repeating --type-add:

$ rg --type-add 'web:*.html' --type-add 'web:*.css' --type-add 'web:*.js' -tweb 'color'

The --type-add flag also supports an include directive to compose types from existing ones:

$ rg --type-add 'src:include:cpp,python,markdown' -tsrc 'pattern'

This creates a src type that matches all files matched by the cpp, python, and markdown types. You can add further globs to the same type:

$ rg --type-add 'src:include:cpp,python' --type-add 'src:*.foo' -tsrc 'pattern'

Type names must consist only of Unicode letters or numbers; punctuation isn't allowed. One glob can be added per invocation of --type-add, but you can use the brace syntax (*.{html,css,js}) to match multiple extensions in one glob.

Important: --type-add only persists for the current command. If you want to use the same type in every ripgrep invocation, see the configuration file approach below.

The --type-list flag: discover available types

To see all available types and their glob patterns:

$ rg --type-list

This prints each type on its own line, followed by a colon and a comma-delimited list of globs. For example:

make: *.mak, *.mk, GNUmakefile, Gnumakefile, Makefile, gnumakefile, makefile
rust: *.rs
python: *.py, *.pyi, *.pyw

If you've used --type-add or --type-clear, those changes appear in the list:

$ rg --type-add 'web:*.html' --type-list | grep web
web: *.html

The list is useful for discovering which types ripgrep recognizes and for verifying the exact globs that make up a type before you use it in a search.

The special "all" type

Both --type and --type-not support a special value all, which acts as a shorthand:

--type all is equivalent to --type agda --type asciidoc --type asm ... for every single type ripgrep knows about. It puts ripgrep into "whitelist" mode: only files matching at least one type are searched. Unrecognized files are skipped.

--type-not all inverts this: only files that don't match any known type are searched. This is "blacklist" mode and is useful when you want to search only custom or unusual file formats that ripgrep doesn't recognize.

Combining file-type filters

You can mix --type and --type-not in a single command:

$ rg 'TODO' --type rust --type python --type-not test

This searches Rust and Python files, but excludes any files matching the test type.

When both whitelist and blacklist filters are present, the whitelist takes precedence: a file must match at least one type you've selected, and must not match any type you've negated.

Making types persistent

Each invocation of --type-add only lasts for that one command. To use the same custom type across multiple searches, add it to your ripgrep configuration file. Set the RIPGREP_CONFIG_PATH environment variable to point to your config file, then add --type-add entries:

# ~/.ripgreprc
--type-add
web:*.{html,css,js}

--type-add
config:*.ini,*.toml,*.yaml,*.yml

Configuration file syntax requires each flag and its value on separate lines. Every line becomes a single argument to ripgrep, so --type-add web:*.html won't work; you must write it across two lines. Comments start with #.

ripgrep prepends your config file to its arguments before parsing, so command-line arguments override the config. Running rg --type-add 'web:*.{html,css,js,md}' -tweb will use your command-line definition of web, not the one from the config.

Precedence and limits

File-type filters have lower precedence than glob patterns. If you write:

$ rg 'pattern' --type rust -g '!*.rs'

The glob negation wins, and no Rust files are searched. Globs also take precedence over .gitignore files and other automatic filtering.

Type filters never modify what ripgrep considers binary files, hidden files, or files in ignore patterns. A type filter says, "search only files of this type," but those files must still pass ripgrep's other filters. If a Rust file is in .gitignore, it won't be searched, even if you use --type rust.

Common patterns

Search a single language:

$ rg 'TODO' --type python

Search multiple related languages:

$ rg 'import' --type rust --type go

Exclude a category of files:

$ rg 'function' --type-not test

Search only recognized file types (no stray files):

$ rg 'query' --type all

Search only unknown file types:

$ rg 'data' --type-not all

Define a custom type for the session:

$ rg --type-add 'logs:*.log' -tlogs 'ERROR'
